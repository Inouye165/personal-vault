## 1. Executive Summary

Stage 7E introduces offline document classification and conservative software/system clutter filtering over already-cataloged documents (`category = 'document'`), building on Stage 7A recorded facts, Stage 7B native text extraction (`doc_extract_v1`), Stage 7C offline OCR (`doc_ocr_v1`), and Stage 5B's two-phase portable `AnnotationJournal`.

### Proposed Approach Summary

1. **Two-Axis Multi-Label Taxonomy**: Replaces the flat placeholder `DocumentPurpose` union in [domain.ts](file:///D:/organizer/src/shared/types/domain.ts#L12-L21) with two orthogonal multi-label axes:
   - **Document Purpose (`purposeLabels`)**: subset of `{'legal', 'lists', 'instructions', 'receipts', 'recipes'}` plus explicit mutually-distinct fallback statuses **`'other'`** (**_"Other / No structured match"_** — readable substantive text was inspected, covering both off-taxonomy readable prose/logs and conservative abstention when structured purpose signals are insufficient) and **`'unknown'`** (**_"Unknown / Unreadable or insufficient text"_** — unextracted, encrypted, unsupported format, empty OCR, or `< 80` chars and `< 4` non-empty lines).
   - **Origin / Context (`originLabels`)**: subset of `{'personal', 'software_project', 'application_system'}` plus **`'unknown'`** when available evidence is insufficient.
2. **Conservative Deterministic Rules First (`doc_classify_rules_v1`)**: Executes 100% offline in a bounded worker thread under `AppWorkerBudget(3)` over already-persisted catalog metadata and Stage 7B/7C extracted/OCR text tracks—requiring **zero new source-file disk reads**, **zero new npm dependencies**, **zero model downloads**, and **zero outbound network access**.
   - Tracks CommonMark fenced code blocks (` ``` ` and `~~~`) across the **full normalized text stream** before selecting head (`64,000` chars) and tail (`16,000` chars) inspection ranges so fence context is never lost across omitted middle ranges.
   - Uses line-oriented heading parsing (`<= 120` chars) and horizontal-whitespace (`[ \t]`) phrase patterns without multiline-spanning backtracking regexes, requiring $\ge 2$ **pairwise-disjoint** corroborating signal families per specific label.
3. **Role of Optional Local Models**: Empirical evaluation on the 32-document synthetic tuning set using the already-cached Stage 7D bi-encoder (`Xenova/bge-small-en-v1.5`, `0` downloads, `0` network calls) shows that revised deterministic rules (`doc_classify_rules_v1_rev4_eval`) achieve **`0 / 23` (`0.0%`) false-hides of valuable personal documents** in **`0.131 ms/doc`**, whereas standalone BGE prototype similarity drops multi-label recall and **falsely hides `1 / 23` (`4.3%`) valuable personal notes**. Stage 7E ships **pure deterministic rules (`doc_classify_rules_v1`) only** across Slices 1–3, deferring optional `hybrid_rules_bge` fallback (which, if ever enabled later, is hard-barred from promoting clutter).
4. **Three-Layer Provenance & Durable User Control**: Strictly separates (1) immutable filesystem/hash facts, (2) revision- and extraction-bound machine classifications (`document_classifications` + `document_classification_labels`, structured `evidence_json`, discrete `confidence_band`, non-overwriting `uncertainty_reasons_json`, exact inspection/omission offsets), and (3) user overrides (`document_classification_overrides` + two-phase `AnnotationJournal` `kind: 'document_classification_override'`). Reclassification and rule upgrades never overwrite user overrides.
5. **Reversible, Non-Destructive Clutter Filtering**: Defaults to **`'show_all'`** (opt-in clutter hiding); never treats `.md`/`.txt` extensions or single path/filename keywords (`dev`, `projects`, `system`, `app`, `README`) as sufficient evidence of clutter; enforces a **`personal` / `recipes` / `receipts` veto** and blocks clutter promotion whenever any input/OCR/truncation/origin uncertainty is present; discloses exact `hiddenClutterCount` alongside **`Show all`** and **`Inspect hidden (N)`** controls; and **never** deletes source files, vault copies, or catalog rows.

## 2. Classification Taxonomy: Orthogonal Axes & Multi-Label Semantics

### 2.1 Why a Single Mutually Exclusive Category Fails

Currently, [domain.ts](file:///D:/organizer/src/shared/types/domain.ts#L12-L21) defines a placeholder flat union (`'personal' | 'software_project' | 'application_system' | 'legal' | 'lists' | 'instructions' | 'receipts' | 'recipes' | 'unclassified'`). Nothing in SQLite or IPC persists this union yet. Forcing these labels into a single mutually exclusive field creates immediate structural defects:

- **Cross-axis collision (`Origin` vs. `Purpose`)**: An open-source `LICENSE.txt` or `THIRD_PARTY_NOTICES.md` is simultaneously `software_project` (origin) and `legal` (purpose). A repository `README.md` is `software_project` and `instructions`. A residential lease is `personal` and `legal`.
- **Within-purpose overlap**: Personal archives combine purposes inside one file—for example, a holiday hosting `.md` note containing a grocery shopping checklist (`lists`), a relish recipe (`recipes`), and oven roasting steps (`instructions`), or a sublease addendum containing a signed security-deposit receipt (`legal` + `receipts`).
- **Conflation of `other` with `unknown`, or misrepresenting abstention**: Treating an encrypted PDF (`password_protected`) identically to readable prose violates Personal Vault Principle #2, while labeling `other` as purely "off-taxonomy prose" would misrepresent narrative documents where conservative deterministic rules abstained due to missing structural headings.

### 2.2 Proposed Two-Axis Multi-Label Schema

| Axis / Field        | Allowed Values                                                    | Multi-Label? | Semantics                                                                                                                                                                                                                                                                  |
| :------------------ | :---------------------------------------------------------------- | :----------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`purposeLabels`** | `'legal'`, `'lists'`, `'instructions'`, `'receipts'`, `'recipes'` | **Yes**      | Zero or more functional document purposes supported by $\ge 2$ pairwise-independent signal families (or $\ge 5$ validated task checkboxes / multi-column CSV/TSV rows).                                                                                                    |
| **`purposeStatus`** | `'classified'` \| `'other'` \| `'unknown'`                        | Single state | `'classified'` iff `purposeLabels.length >= 1`; **`'other'`** (**_"Other / No structured match"_**) when readable substantive text was inspected, covering both off-taxonomy readable prose/logs and conservative rule abstentions; **`'unknown'`** when unreadable/short. |
| **`originLabels`**  | `'personal'`, `'software_project'`, `'application_system'`        | **Yes**      | Zero or more origin/context labels. Allows mixed provenance (e.g., personal notes or freelance contracts inside a project directory).                                                                                                                                      |
| **`originStatus`**  | `'classified'` \| `'unknown'`                                     | Single state | `'classified'` iff `originLabels.length >= 1`; `'unknown'` when origin cannot be established conservatively from available text and corroborated metadata.                                                                                                                 |

### 2.3 Assessment of Overlapping Label Combinations

1. **Cross-Axis Overlaps (`originLabels` $\times$ `purposeLabels`) — Expected & First-Class**:
   - `['software_project']` $\times$ `['legal']`: `LICENSE`, `COPYING`, `THIRD_PARTY_NOTICES.md`.
   - `['software_project']` $\times$ `['instructions']`: package `README.md`, `INSTALL.md`, container/deployment runbooks.
   - `['software_project']` $\times$ `['lists']`: engineering `TODO.md`, sprint release checklists.
   - `['application_system']` $\times$ `['legal']`: bundled device-driver or installer `EULA.rtf`.
   - `['personal']` $\times$ `['legal' | 'lists' | 'instructions' | 'receipts' | 'recipes']`: household leases/contracts, shopping/inventory lists, appliance/medical care guides, consumer/medical receipts, and recipes.
2. **Within-Purpose Overlaps (`|purposeLabels| >= 2`) — Preserved Without Forced Ranking Loss**:
   - `['recipes', 'lists', 'instructions']`, `['legal', 'receipts']`, `['receipts', 'lists']`, and `['legal', 'instructions']` are persisted and displayed deterministically by `(confidenceBand DESC, weightSum DESC, label ASC)`, with **every** matched label searchable via SQL `EXISTS` filters.
3. **Mixed-Origin Overlaps & Weak Personal-Protection Veto (`|originLabels| >= 2` or mixed signals)**:
   - **Distinction Between Weak Veto and Asserted `'personal'` Origin**: A single weak personal family (`personalFamilies.size === 1`), or a `recipes` / `receipts` purpose, sets **`has_personal_veto = true`** (unconditionally blocking `is_clutter_candidate = true`) **without** promoting `'personal'` into `originLabels` when competing `software_project` or `application_system` signals (`>= 2` families) are present. Assertive `'personal'` in `originLabels` requires `personalFamilies.size >= 2` (or `personalFamilies.size >= 1` when no competing origin reaches `>= 2` families).
   - When `personalFamilies.size === 1` co-occurs with `>= 2` software/system families (e.g., a repository `README.md` mentioning a `"living room"` sensor node), `'personal'` is withheld from `originLabels`, `has_personal_veto = true` keeps `is_clutter_candidate = false`, and `uncertaintyReasons` records both `'overlapping_origin_signals'` and `'single_weak_signal_abstained'`.

## 3. Offline Classification Approach & Resolution of Review Findings

### 3.1 Baseline: Conservative Deterministic Rules (`doc_classify_rules_v1`)

The primary classifier is a pure, deterministic, versioned rule engine executing off the Electron main thread:

- **Strictly Offline, Zero-Touch Inputs**:
  - Reads already-cataloged `file_locations` / `sources` metadata (`file_name`, `extension`, `byte_size`, and **source-root-relative path** `relative(sourceRootPath, originalPath)` so ancestor folder names above an explicitly selected root never influence classification, matching Stage 2A's discovery boundary in [policy.ts](file:///D:/organizer/src/main/services/discovery/policy.ts#L237-L240)) plus already-persisted Stage 7B `document_extractions` (`native`) and Stage 7C `document_ocr_extractions` (`ocr`, including `mean_confidence`, `truncated`).
  - **Zero new source-file opens**: Originals on disk are never opened during classification, guaranteeing zero `atime` churn and working even when removable media is unplugged.
- **Honest Abstention Floor (`unknown`) & Multi-Reason Preservation**:
  - Whenever both `native` and `ocr` tracks are absent, non-current, failed, `password_protected`, `unsupported`, `no_text_ocr_required` / `ocr_no_text`, or yield `< 80` inspected characters and `< 4` non-empty lines, the classifier abstains (`purposeStatus = 'unknown'`, `originStatus = 'unknown'`, `confidenceBand = 'low'`, `isClutterCandidate = false`) while **preserving all simultaneous input uncertainty flags** (`'no_extracted_text'` / `'insufficient_text_length'` alongside `'upstream_truncated_input'`, `'truncated_input'`, `'unclosed_code_fence'`, `'ocr_low_confidence'`, and `'ocr_confidence_missing'`).
- **Full-Stream CommonMark Fenced-Code Tracking & Accurate Range Disclosure (Review Finding 2 Resolution)**:
  - Rather than slicing `head` and `tail` first and resetting `tail` to "outside code," `scanTextWithFenceContext` ([rules-prototype.mjs](file:///D:/organizer/spikes/doc-classification-eval/rules-prototype.mjs#L98-L227)) walks line boundaries (`indexOf('\n')`) across the **entire available normalized text** (`<= 500,000` chars per Stage 7B/7C extraction limits), inspecting at most the first `256` chars of each line via character-code checks (`0..3` leading spaces + `>= 3` backticks `` ` `` or tildes `~`, enforcing CommonMark info-string backtick prohibition and matching marker character + minimum length on closing fences).
  - Exact character ranges are preserved: `headRange = [0, min(N, 64_000))`, `omittedRange = N > 80_000 ? [64_000, N - 16_000) : null`, `tailRange = N > 80_000 ? [N - 16_000, N) : null`, satisfying **`inspectedHeadChars + omittedChars + inspectedTailChars === totalNormalizedChars`**.
  - Fences opening in `head` or inside the omitted middle `[64_000, N - 16_000)` keep `activeFence` open on entry into `tail` (`tailEnteredInsideFence = true`), keeping code before a closing fence out of `proseLines`, preserving useful prose **after** a closing fence in `tail`, and recording `'unclosed_code_fence'` (`unclosedFenceAtEof = true`) when a fence remains open at EOF.
- **Line-Oriented Parsing & Pathological-Input Safety (Review Finding 1 Resolution)**:
  - All multiline-spanning heading regexes (`^\s*(?:#+\s*)?[\w\s-]*...$/im` and `[^\n]*\b...\b[^\n]*`) and `[\s\S]{0,2000}` gap constructs were **removed** across the prototype.
  - Standalone section headings are parsed per line via `normalizeHeadingLine` (`trimmed.length <= 120`, rejecting list bullets, prose sentences ending in `.`, and non-`#` key-value lines with mid-line `:`), followed by plain string equality/prefix/suffix or short horizontal-whitespace (`[ \t]`) checks. All multi-word body patterns use horizontal `[ \t]` whitespace rather than newline-spanning `\s`, and two-part document checks (e.g., MIT grant + `"the \"Software\""`, or EULA header + installer/driver context) evaluate two independent non-spanning phrase checks.
- **OCR Confidence Caps & Uncertainty Clutter Guard (Review Finding 3 Resolution)**:
  - When classification relies on an OCR track (`textSourceKind === 'ocr'`):
    - `ocrMeanConfidence >= 80`: uncapped (`'high'` permitted when signal families warrant it).
    - `60 <= ocrMeanConfidence < 80`: appends `'ocr_low_confidence'` to `uncertaintyReasons` and caps `confidenceBand` at **at most `'medium'`**.
    - `ocrMeanConfidence < 60`: appends `'ocr_low_confidence'` to `uncertaintyReasons` and caps `confidenceBand` at **at most `'low'`**.
    - `ocrMeanConfidence` missing (`null`, `undefined`, or non-finite on an OCR track): appends `'ocr_confidence_missing'` to `uncertaintyReasons` and caps `confidenceBand` at **at most `'medium'`**.
  - **Uncertain-Input Clutter Disqualification**: `is_clutter_candidate` is forced to **`false`** whenever `confidenceBand !== 'high'` OR `uncertaintyReasons` contains **any** input or origin uncertainty (`'no_extracted_text'`, `'insufficient_text_length'`, `'truncated_input'`, `'upstream_truncated_input'`, `'unclosed_code_fence'`, `'ocr_low_confidence'`, `'ocr_confidence_missing'`, or `'overlapping_origin_signals'`).
- **Pairwise-Disjoint Signal Families & Zero Corpus-Specific Literals (Review Finding 4 Resolution)**:
  - All corpus-specific literals (`"pat turkey dry"`, `"position the rack"`, `"cranberry-orange"`, `"hosting plan"`, `"descaling guide"`, `"notes for our cpa"`, `"run robocopy"`, `"nonna"`, `"parmigiano"`, `"bread flour"`, `"granulated sugar"`, `"canine"`, `"rabies"`, `"ibuprofen"`, `"dry cleaning"`, `"library books"`, `"steam wand"`, `"water tank"`, `"KERNEL32.DLL"`, `"NamedPipe IPC"`) were removed without example-specific replacements.
  - Signal families within every purpose and origin label were audited for **strict pairwise independence** so no single token, phrase, or line occurrence can satisfy $\ge 2$ families of the same label:
    - **`receipts`**: (R1) monetary summary line (`Subtotal` / `Total` / `Balance Due` / `Amount Paid` / `Co-Pay`, OCR `0`/`O` tolerant), (R2) $\ge 3$ **non-summary, non-tax** itemized price lines, (R3) payment card/method/auth or tax line (`VISA`/`V1SA`, `Mastercard`, `AMEX`, `Sales Tax`, `Auth #`), (R4) receipt/invoice/statement/transaction identifier. Requires $\ge 2$ families including R1 or R2.
    - **`recipes`**: (C1) standalone `Ingredients` heading, (C2) $\ge 2$ culinary unit patterns (`tbsp`/`tsp`, `cup`, `grams`/`oz`/`lb` + word, `pinch`/`cloves`/`sprigs`/`handful`), (C3) $\ge 2$ cooking process/oven-temperature/timing markers (`Preheat oven`, `350°F`/`230°C`, `simmer`/`whisk`/`knead`/`bake for`/`roast until`, `Prep time`/`Servings`).
    - **`legal`**: (L1) formal clauses (`WHEREAS`, `IN WITNESS WHEREOF`, `governing law`, `severability`, `indemnify`, `limitation of liability`), (L2) contract/agreement party roles or titles (`Landlord`/`Tenant`, `Sublessor`/`Sublessee`, `Licensor`/`Licensee`, `Lease Agreement`, `Consulting Agreement`, `End-User License Agreement`), (L3) OSS license title or `SPDX-License-Identifier:` header, (L4) operative OSS grant/warranty disclaimer (`Permission is hereby granted...`, `WITHOUT WARRANTY OF ANY KIND`, Apache compliance clause), (L5) signature/execution attestation (`Signed:`, `Signature:`, `/s/`, `Notary Public`).
    - **`lists`**: (T1) $\ge 4$ Markdown checkboxes (`- [ ]` / `- [x]`), (T2) $\ge 4$ consistent `.csv`/`.tsv` multi-column rows, (T3) standalone list/checklist/backlog/grocery/inventory heading or filename, (T4) $\ge 3$ **non-checkbox** bullet/numbered lines at $\ge 60\%$ prose-line density (excluding recipes and `Step 1:` manuals).
    - **`instructions`**: (I1) multi-step sequence (`Step 1:` + `Step 2:`, or `1.` + `2.` excluding all-caps contract article headers like `1. GRANT OF LICENSE:`), (I2) standalone procedural heading (`Instructions`, `Directions`, `Prerequisites`, `Installation`, `Setup`, `Usage`, `Troubleshooting`, `Safety Warnings`, `* Guide`, `* Manual`, `* Steps`), (I3) imperative procedural verbs evaluated **exclusively on non-heading prose lines** paired with steps or code blocks.
    - **`personal` (Origin — 3 disjoint domains)**: (P1 `personal_finance_medical_or_culinary`) `recipes`/`receipts` purpose or clinical/medical/veterinary/personal-tax terms (`patient`, `clinic`, `dental`, `veterinary`, `surgery`, `discharge`, `prescription`, `cpa`, `tax return`, `1099`, `w-2`); (P2 `personal_family_or_social_narrative`) kinship, neighbors/guests, or personal reflection/diary/eulogy (`family`, `mom`, `dad`, `uncle`, `spouse`, `guests`, `neighbors`, `eulogy`, `diary`, `journal`, `personal reflection`); (P3 `personal_residence_or_household`) residential property, rooms (`living room`, `bedroom`, `kitchen`, `garage`, `backyard` — `"living room"` exists **only** in P3), household appliances/Wi-Fi, or groceries/home insurance.
    - **`software_project` (Origin)**: (S1) developer CLI/module syntax **strictly inside `fencedText`**, (S2) repository URL / `SPDX-License-Identifier:` / `package.json` / `tsconfig` / `eslint` / `vitest` / PR metadata in prose, (S3) verbatim MIT/Apache software grant body, (S4) canonical repo filename/path (`README.md`, `ARCHITECTURE.md`, `THIRD_PARTY_NOTICES.md`, `LICENSE.txt`, `TODO.md`, `repos/`, `code/`) **counted only when corroborated by S1–S3**.
    - **`application_system` (Origin)**: (A1) $\ge 3$ structured ISO `[INFO]`/`[WARN]`/`[ERROR]` daemon log lines, (A2) PID/TID/exception-code/stack-trace/exit-code telemetry, (A3) EULA header paired with installer/driver/setup-wizard markers, (A4) system log/crash/installer relative path **counted only when corroborated by A1–A3**.

## 5. Conservative Clutter Filtering Policy

- **Post-Discovery Scope**: Stage 2A ([policy.ts](file:///D:/organizer/src/main/services/discovery/policy.ts#L48-L119)) already skips `node_modules`, `.git`, `dist`, `venv`, `CMakeLists.txt`, `requirements.txt`, and `CHANGELOG.md` at scan time. Stage 7E operates reversibly on remaining cataloged documents (`README.md`, `ARCHITECTURE.md`, `TODO.md`, `LICENSE.txt`, `THIRD_PARTY_NOTICES.md`, `EULA.rtf`, daemon logs, crash dumps).
- **Mandatory Conjunction for `is_clutter_candidate = true`**:
  1. `clutter_override !== 'force_keep'` and effective origins exclude `'personal'`.
  2. Machine origin includes `'software_project'` or `'application_system'` at `confidence_band === 'high'` backed by $\ge 2$ independent families (at least one verified content-structural family).
  3. Zero standalone weight for `.md`/`.txt`/`.csv`/`.pdf`/`.docx` extensions or single path/filename tokens (`dev/`, `projects/`, `system/`, `app/`, `README.txt`).
  4. `has_personal_veto === false` (zero `'personal'` origin families, zero `recipes` or `receipts` purposes).
  5. **Zero disqualifying uncertainty**: `uncertaintyReasons` contains none of `{'no_extracted_text', 'insufficient_text_length', 'truncated_input', 'upstream_truncated_input', 'unclosed_code_fence', 'ocr_low_confidence', 'ocr_confidence_missing', 'overlapping_origin_signals'}` and no mixed-folder propagation occurs.
- **Reversible UX & Non-Destructive Invariants**:
  - Defaults to **`'show_all'`**; toggling `'hide_clutter'` applies a pure SQL `WHERE` filter, discloses exact `hiddenClutterCount` with one-click **`Show all`** and **`Inspect hidden (N)`** (`'only_clutter'`), and **never** deletes source files, vault copies, or catalog records.

## 8. Locked Baseline Decisions & Known Limitations (`Stage 7E Complete`)

### Locked Baseline Decisions

1. **Default Clutter Filter State**: **`'show_all'`** (opt-in clutter hiding; zero documents hidden by default).
2. **Initial Classifier Scope**: **Pure deterministic rules (`doc_classify_rules_v1`) only** across Slices 1–3 (zero model dependency; optional `hybrid_rules_bge` deferred).
3. **Stage 7D Semantic Search Integration**: `purposeFilter`, `originFilter`, and `clutterFilter` prune candidates in SQL **before** chunk ranking, revalidate classification/override currency in `revalidateScoredSearchItem`, and disclose active clutter filtering honestly without unranked `"hidden matches"` counts.
4. **`'other'` vs. `'unknown'` Presentation**: Exposed as distinct filter options labeled **`"Other / No structured match"`** (`'other'`, covering both off-taxonomy readable prose/logs and conservative rule abstentions) vs. **`"Unclassified / Needs text extraction or OCR"`** (`'unknown'`).

### Known Limitations Retained

- **Synthetic Evaluation Scope & Precision-First Clutter Coverage**: Current measurements come from a 32-document synthetic tuning corpus and 21 synthetic adversarial regression groups; the `>= 60`-document frozen-hash held-out validation suite has **not yet been authored or executed** (scheduled for Slice 1), and real-world personal archives will contain layouts and languages beyond English rules. Adopting the precision-first clutter scope (`>= 50%` overall held-out clutter recall; `>= 80%` on the observable multi-signal whole-document boilerplate subset) reduces initial clutter-filter coverage—ambiguous single-content-family `README`, `TODO`, `EULA`, and non-`SPDX` license files abstain conservatively and remain visible—and does not improve the measured `55.6%` tuning recall or establish generalization.
- **Conservative Prose Recall Bound**: Pure deterministic rules intentionally abstain to `'other'` (_Other / No structured match_) on unstructured narrative recipes, informal plain-English agreements, and narrative medical instructions lacking structural headings or units (`80.0%–85.7%` recall on tuning-set `lists`/`legal`/`instructions`, `66.7%` on `recipes`).
- **Empirical Timing Scope**: Measured `< 5.4 ms` timings at `500,000` chars reflect empirical V8 execution on the test host rather than a formal proof of worst-case regex complexity; production `DocumentClassificationWorkerRunner` retains a hard worker timeout and `AppWorkerBudget(3)` isolation as defense-in-depth.
- **Single-Catalog-Owner Snapshot Cleanup Tracking**: `DocumentClassificationRepository.inFlightSnapshotJobIds` is tracked per repository instance in memory (safe under the single main-process `CatalogDatabase` owner, not cross-process or multi-instance).
- **UI End-to-End Narrow-Viewport & Override-Editor Scope**: Responsive modal drawer support uses `useMediaQuery('(max-width: 900px)')`, but `verify-electron-doc-classify-ui.mjs` does not explicitly resize to `480x820` or exercise the multi-select `"Edit classification"` checkboxes end-to-end.
