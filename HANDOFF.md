## 5. Supported User Workflow & Known Limitations

### 5.1 Supported Offline Photo-Search User Workflow

1. **Scan Source Folders (`Sources & Scan`)**: Register one or more read-only source directories and execute a scan job to record verbatim filenames, paths, byte sizes, filesystem timestamps, and verified SHA-256 hashes.
2. **Provision Pinned Semantic Model (`Photos` -> `Semantic Index`)**: Explicitly import an offline model directory (`semantic:import-model-folder`) or run a one-time checksum-verified download (`semantic:download-model`) of `Xenova/clip-vit-base-patch32` (`6b7c523703ae26e39be4b03774966f8571c7f523`, 7 files, `155,851,918` bytes / `148.63 MiB`) into `<userData>/models/`. If a model installation is missing or damaged, `PhotosSearchBar` displays an explicit recovery notice (`[data-testid="search-model-missing-notice"]` or `[data-testid="search-model-corrupt-notice"]`).
3. **Extract Technical Metadata & Index Photos (`Photos`)**:
   - Run **Extract Metadata** (no model required) to parse EXIF/header capture dates, camera/lens names, orientation-adjusted display dimensions, and container formats.
   - Run **Index Photos** to compute 512-dimensional L2-normalized CLIP embeddings (`clip_vit_b32_224_bicubic_center_rgb_v1`). Both jobs support pause, cancel, resume, and startup crash recovery with exact snapshotted scope.
4. **Search, Filter & Browse (`Photos` Toolbar & Grid)**:
   - Enter a natural-language query ($\le 500$ chars) and combine with Stage 5B (rating, flag, collection) and Stage 6C (capture date range, camera, lens, display resolution, file-type basis, `Unknown`) filters.
   - SQL filters prune candidates before cosine similarity ranking (`TopKMinHeap` for `offset + limit <= 1,000`; disk-backed temporary SQLite ranker for `offset + limit > 1,000`).
   - Clear the search bar at any time to return to ordinary browsing.

### 5.2 Known Limitations & Evidence Disclosures

- **Uncalibrated Machine Inferences**: Cosine similarity badges (`xx% match`) are AI inferences, not factual labels or calibrated probabilities.
- **77-Token CLIP Context Window**: Queries exceeding 77 BPE tokens are truncated to 77 tokens and disclosed via `truncated: true` and `tokenCount: 77`.
- **Format Coverage**: JPEG, PNG, WebP, GIF (frame 0), AVIF, TIFF, and Apple HEIC/HEIF (via bundled `libheif-js@1.23.5`) are supported. Camera RAW formats (and SVG/BMP) are reported honestly as `unsupported`.
- **Synthetic vs. Real Scale Fixtures**: Relevance queries in `verify:semantic-search` run against 10 real raster photos (plus 4 fresh real photos in `overlap_photos/`) indexed through `sharp` and `onnxruntime-node`; deep pagination (`offset: 10050` over `10,214` items in Electron; `50,001` items in Vitest) uses deterministic unit-normalized synthetic 512-d vectors in SQLite so large-catalog ranking, disk-backed paging, and virtual grid LRU eviction can be verified deterministically without a 50,000-photo fixture repository (kept distinct from Stage 5A's `10,000`-photo real-decodable-image thumbnail verification `verify:photos`).
- **Memory & Controlled Test Delay Scope**: In `Phase 10b` only, controlled env-gated test delays (`PV_TEST_SEARCH_DELAY_MS=250` in `search-worker.ts`, `PV_TEST_WORKER_METADATA_DELAY_MS=120`, `PV_TEST_WORKER_SEMANTIC_DELAY_MS=120`, `PV_TEST_WORKER_THUMBNAIL_DELAY_MS=120` in `thumbnails/worker.ts`) are activated to reliably observe simultaneous 4-way workload overlap and 16-request queue saturation; normal production runs leave all `PV_TEST_*` variables unset, and `Phase 11`–`Phase 13` relaunch with zero test delays. V8 heap measurements in scale tests are point samples before/after ranking, while worker/queue counts, `rAF` frame intervals (`p95 <= 33 ms`), and main-process event-loop delays (`p95 < 100 ms`, `max < 200 ms`) are sampled continuously across active runs.
- **OS `atime` Updates**: Source files are strictly read-only (`size`, `sha256`, `birthtimeMs`, `mtimeMs` 100% invariant); Windows NTFS may update `atimeMs` on read-only opens.
